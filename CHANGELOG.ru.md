# Changelog

Все заметные изменения ReactX. Версии — [Semantic Versioning](https://semver.org/lang/ru/): `MAJOR.MINOR.PATCH`, теги в git — `vMAJOR.MINOR.PATCH`. С 1.0 несовместимые изменения поднимают `MAJOR`, новые возможности — `MINOR`, исправления — `PATCH` (до 1.0 несовместимые изменения поднимали `MINOR`).

In English: [CHANGELOG.md](CHANGELOG.md).

## [Не выпущено]

### Изменено

- Терминальные приложения с большим деревом быстрее: коммит больше не обходит всё дерево дважды, чтобы поправить фокус (рендерер считает узлы, которые могут взять или удержать фокус, и обходит дерево, только когда фокусный узел исчезает или появляется ловушка). 20 новых строк в прокручиваемом логе из 10 000 строк: 32,7 → 12,0 мс.
- Хуки быстрее: хук и зависимости эффекта проверяются сравнением одного указателя (метки типа), а не `dynamic_cast` на каждом рендере; значения контекста и typed props сравниваются так же. В самом ReactX больше нет `dynamic_cast`.

## [1.5.0] — 2026-11-07

Ещё восемь библиотек, которые идут вместе с ReactX, — для фронтенда (проверка форм, выбор даты, перетаскивание, анимации) и для серверов (JSON API, вход, логи, настройки) — и адрес клиента в `net::Request`. В существующих приложениях ничего не меняется.

**Обновление:** `reactx upgrade`, затем `reactx update` в каждом проекте; подключите нужные библиотеки (`target_link_libraries(my_app PRIVATE reactx::forms reactx::calendar)`, сервер: `reactx::api reactx::auth reactx::config`).

### Добавлено

- `reactx::motion` в `library/motion` (`rx/motion.hpp`): `presence` (Fade, Slide, Scale, Collapse — CSS-переходы в браузере с учётом «уменьшения движения»; терминал показывает и скрывает сразу), `useTween` и `useSpring` для плавно меняющихся значений, функции сглаживания. Подключение: `reactx::motion`.
- `reactx::dnd` в `library/dnd` (`rx/dnd.hpp`): `sortable` — порядок списка перетаскиванием мышью (браузер и терминал) или Alt+↑ / Alt+↓; `moved`. Подключение: `reactx::dnd`.
- `reactx::calendar` в `library/calendar` (`rx/calendar.hpp`): `calendar` (сетка месяца с min / max / недоступными днями, навигацией с клавиатуры, одной остановкой Tab) и `datePicker`, на языке `reactx::i18n`; `today()`. Подключение: `reactx::calendar`.
- Страница библиотек (`web_libraries.html`) показывает также forms, calendar, dnd и motion.
- llms.txt: библиотеки в одной таблице (заголовок, где работает, с какой версии), UI- и серверные — отдельно.
- `reactx::log` в `library/log` (`rx/log.hpp`): структурные логи — `debug` / `info` / `warn` / `error` с полями `key=value`, текстом или строками JSON (`setup({.json = true})`), уровень из `LOG_LEVEL` (`levelFromEnv`), свой вывод; потокобезопасно. Подключение: `reactx::log`.
- `reactx::config` в `library/config` (`rx/config.hpp`, нативная): настройки из аргументов (`--port 9000`), переменных окружения (`APP_PORT`) и JSON-файла (вложенные ключи как `db.path`) в этом порядке; `text`, `number`, `flag`, `require` / `requireNumber` (`std::expected` с тем, где искали), `positional`, `source`. Подключение: `reactx::config`.
- `reactx::auth` в `library/auth` (`rx/auth.hpp`, нативная): `hashPassword` / `verifyPassword` / `needsRehash` (PBKDF2-HMAC-SHA256, 600 000 раундов, случайная соль, сравнение за постоянное время), `Sessions` (cookie с HttpOnly и SameSite, новый id при каждом входе, истечение по простою и общему сроку, `endAll` — выйти везде; потокобезопасно), middleware `requireLogin` и `csrf` для `reactx::api`, а также `randomToken`, `sha256Hex`, `hmacSha256Hex`, `constantTimeEquals`. Проверено на тестовых векторах NIST, RFC 4231 и RFC 7914. Подключение: `reactx::auth`.
- `reactx::api` в `library/api` (`rx/api.hpp`, нативная): JSON API на `HttpServer` — `Router` (маршруты под префиксом, middleware, маршруты `OPTIONS` для preflight), `catchErrors`, `cors`, `rateLimit` (429 с `Retry-After`), `log`, `body(request, schema)` (400 / 415 / 422 с ошибками полей), `intParam`, `clientAddress` и ответы `ok` / `error` / `invalid` / `noContent`. Подключение: `reactx::api`.
- `net::Request::remote`: IP-адрес клиента.
- `reactx::forms` в `library/forms` (`rx/forms.hpp`): правила проверки (`required`, `minLength`, `maxLength`, `email`, `url`, `digits`, `oneOf`, `min`, `max`, `accepted`, свои через `rule`) и `Schema<T>` для структуры — `.field(name, &T::member, {правила})`, `.check(name, f)` для нескольких полей, `.validator()` для `ui::useForm` — плюс `JsonSchema` для JSON от клиента (типы, необязательные поля, `toJson` для ответа 422). Сообщения меняются один раз (`messages()`). Подключение: `reactx::forms`.

## [1.4.0] — 2026-11-06

Иконки, страница со всеми библиотеками вживую и более лёгкая `reactx::i18n`. В существующих приложениях ничего не меняется.

**Обновление:** `reactx upgrade`, затем `reactx update` в каждом проекте; `target_link_libraries(my_app PRIVATE reactx::icons)` для иконок.

### Добавлено

- На сайте есть страница с библиотеками вживую — `web_libraries.html` (ссылка с /demos; `#icons` и подобные открывают вкладку): `reactx::query` с кэшем на два списка, оптимистичным обновлением и его откатом, редактор Markdown с предпросмотром, графики, все иконки и форматы i18n на 10 языках. Это отдельная страница, поэтому `.wasm` сайта библиотеки не несёт.
- `reactx::icons` в `library/icons` (`rx/icons.hpp`): `icon({.name})` — 51 линейная иконка, нарисованная для ReactX (действия, стрелки, статусы, предметы, медиа): inline SVG в браузере, который берёт цвет и размер текста (`.size`, `.color`, `.label` для экранных дикторов, `.spin` для индикаторов загрузки), и символ в одну клетку в терминале. `names()` перечисляет их, `add(name, path, symbol)` добавляет свои. Подключение: `reactx::icons`.

### Изменено

- ReactX представляется как «React на C++» (сайт, README, демо, шаблоны проектов, описание репозитория); C++26 называется там, где это важно, — нужные компиляторы и используемые возможности (контракты, рефлексия).
- `reactx::i18n` стоит меньше в `.wasm`: встроенные данные 10 языков — постоянные таблицы, `Locale` создаётся только для запрошенного языка, а `parseMessages` / `loadMessages` / `languagePicker` лежат в отдельных файлах, так что приложение, которое их не вызывает, больше не тянет `rx::fetch`, JSON-парсер и `rx::ui` (сайт ReactX: +2,5 КБ gzip за переключатель языка, а не +22 КБ). Сайт хранит язык в `reactx::i18n`.

### Исправлено

- `reactx::i18n` в браузере: JavaScript у `systemLanguage()` и `<html lang>` не разбирался (`!==` разорвал форматтер кода), и web-сборка с i18n не компоновалась. JavaScript в библиотеках теперь защищён от форматирования.

## [1.3.0] — 2026-11-06

Ещё две библиотеки, которые идут вместе с ReactX, — данные с сервера с кэшем и Markdown — и более быстрая сборка с ccache. В существующих приложениях ничего не меняется.

**Обновление:** `reactx upgrade`, затем `reactx update` в каждом проекте; потом `target_link_libraries(my_app PRIVATE reactx::query reactx::markdown)` для нужных библиотек.

### Добавлено

- `reactx::markdown` в `library/markdown` (`rx/markdown.hpp`): `view({.text})` показывает Markdown — семантический HTML в браузере (с небольшим CSS, который легко перебить), цвета и отступы в терминале. Основы CommonMark плюс таблицы, списки задач, зачёркивание и голые ссылки из GitHub; HTML показывается как текст, ссылки `javascript:` отбрасываются, так что текст от пользователей безопасен. `.link` делает внутренние ссылки ссылками роутера; `parse()` даёт документ (заголовки с id — для оглавления), `plainText()` убирает разметку. Подключение: `reactx::markdown`.
- `reactx::query` в `library/query` (`rx/query.hpp`): данные с сервера с общим кэшем, как React Query / SWR. `useQuery({.key, .url})` даёт `data`, `error`, `loading`, `fetching`, `refetch()`; компоненты с одним ключом делят один запрос; данные из кэша показываются сразу и обновляются в фоне; повторы с паузами, `staleTime`, `cacheTime`, `refetchInterval`, `enabled`, свой тип данных через `.parse`, свой загрузчик через `.load`. `useMutation` для POST/PUT/DELETE с `invalidates` и оптимистичными обновлениями (`onMutate` возвращает откат); `invalidate`, `setData`, `getData`, `updateData`, `remove`, `clear` работают откуда угодно. Подключение: `reactx::query`.
- Сборка быстрее с [ccache](https://ccache.dev): если он установлен, ReactX и приложения из `reactx_add_app` компилируются через него, и повторная сборка того же кода (чистая `build/`, новый проект) занимает секунды — сборка нового web-проекта с нуля 13 → 6 с, самого ReactX 37 → 15 с. `-DREACTX_CCACHE=OFF` выключает; свой `CMAKE_CXX_COMPILER_LAUNCHER` важнее. Код самого ReactX больше не сканируется на C++-модули (ccache не кэширует такую компиляцию); `import reactx;` работает как раньше.

## [1.0.0] — 2026-11-02

ReactX 1.0: API стабилен. Всё, что объявлено в `include/reactx/` вне `detail`, команды `reactx`, `reactx.json` и CMake-функции теперь меняются только в MAJOR-релизе — до 2.0 ничего не переименовывается и не удаляется (README, «Стабильность API»; за этим следят снимок `api/reactx.api` и тест `reactx_api_check`). В релизе также исправления последнего раунда пробных приложений: поля пароля, стрелки в терминальной радиогруппе, `router::redirectedFrom()` для страниц входа, `.error` у `ui::slider` и правка CSS, доходящая до `dist` без изменений в C++.

**Обновиться:** `reactx upgrade`, затем `reactx update` в каждом проекте. Приложения для 0.21 собираются без изменений.

### Добавлено

- `ui::input` `.type`: `ui::InputType::Password` показывает точки в терминале и становится полем пароля в браузере; `Email`, `Number`, `Search`, `Tel` и `Url` выбирают клавиатуру телефона.
- `ui::slider` `.error`, как у всех остальных полей формы.
- `router::redirectedFrom()`: путь (с query), с которого `.redirect` guard'а увёл пользователя, чтобы страница входа вернула его туда; `""` снова после любой другой навигации.
- Терминальный проп `arrowKeys=true`: пока узел в фокусе, ↑ ↓ приходят в его `onKey`, а не двигают фокус.
- Документация: как собрать свой сервер рядом с веб-приложением (нативная цель CMake) и какое место выбирает `testing::Screen::click`.

### Изменено

- `ui::radioGroup` в терминале — одна остановка Tab, как в браузере: фокус у выбранного варианта, стрелки (↑ ↓ ← →) выбирают следующий или предыдущий, по кругу.
- Клик по подписи `ui::input` / `ui::textarea` в терминале ставит фокус в поле, как `<label>` в браузере.
- `ui::text` в браузере сохраняет переносы строк (как в терминале).

### Исправлено

- `reactx build` / `reactx dev` копируют изменённый файл из `public/` (правку CSS) в `dist`, даже если C++ не менялся; раньше в `dist` оставался старый файл до следующей сборки программы.
- Стрелки ничего не делали в терминальном `ui::radioGroup` (в документации — «↑ ↓»): терминал сначала забирал ↑ ↓ для перемещения фокуса.
- Новые проекты: у страницы свой фон и цвет текста (`Canvas` / `CanvasText`), и проверки контраста (Lighthouse, axe) видят фон тёмной темы — раньше подписи `rx::ui` не проходили color-contrast в тёмной теме.
- `ui::progress` в узкой строке терминала обрезал подпись или проценты; теперь укорачивается полоса.

## [0.21.0] — 2026-11-02

Последний релиз перед 1.0: проверка безопасности `HttpServer`, доступный сайт и `rx::ui` (axe-core: 0 нарушений, светлая и тёмная темы, компьютер и телефон), полная документация на двух языках и замороженный публичный API (`api/reactx.api`). MINOR-релиз, потому что `HttpServer` теперь отказывает незнакомым именам в `Host` и чужим `Origin`.

**Обновиться:** `reactx upgrade`, затем `reactx update` в каждом проекте. Серверу, к которому обращаются по доменному имени (не `localhost` и не IP), нужен `server.allowHosts({"example.com"})` или `--allow-host` для `reactx dev` / `reactx_serve`.

### Изменено

- `HttpServer` (а с ним `reactx dev` и `reactx_serve`) отвечает только на `localhost`, `*.localhost` и IP-адреса; другие имена в `Host` получают 403, и сайт, направивший своё DNS-имя на `127.0.0.1`, не прочитает ваш dev-сервер (DNS rebinding). Другие имена: `server.allowHosts({...})` / `reactx dev --allow-host ИМЯ`; домен GitHub Codespaces `reactx dev` разрешает сам.
- WebSocket и запросы кроме GET/HEAD/OPTIONS, чей `Origin` — другой сайт, получают 403 (CSRF, перехват WebSocket с чужого сайта). Страницы с `localhost` на любом порту работают как раньше.
- Файлы с точкой (`/.env`, `/.git/...`) `serveDirectory` не отдаёт; `/.well-known/` отдаёт.
- Доступность (axe-core — движок проверки Lighthouse: 0 нарушений на сайте, в демо и в новом проекте, в светлой и тёмной теме, на десктопе и телефоне): цвета текста `rx::ui` держат контраст 4.5:1 в обеих темах — у каждого имени цвета терминала в `ui::Theme` есть светлый и тёмный оттенок (переменные `--rx-c-*`), у тёмной темы свои акцент, цвет ошибки и успеха, светлый цвет успеха темнее. `ui::themeProvider` записывает только изменённые приложением цвета, и цвета по умолчанию следуют тёмной теме страницы.
- Шаблоны страниц новых проектов и демо монтируют приложение в `<main id="app">` (главный ориентир страницы); пререндер находит и `<main id="app">`, и старый `<div id="app">`.

### Добавлено

- Заморозка API перед 1.0: `api/reactx.api` — снимок публичных заголовков, тест `reactx_api_check` падает, если они изменились без него.
- Документация: описаны `router::useParams`, `currentPath`, `href`, `reset`, `link .activeClassName`, `HttpServer::post/put/patch/del`, `setNotFoundPage`, `setLogging`, `.step/.showValue` у `ui::slider`, `ui::useTheme`; у английской и русской документации одинаковые разделы.
- `ui::CardProps::level` — уровень заголовка карточки в браузере (по умолчанию `<h3>`; 2 для карточек сразу под `<h1>` страницы, чтобы уровни не пропускались).
- `HttpServer::allowHosts`, `setRequestTimeout` (по умолчанию 30 с) и `setMaxConnections` (по умолчанию 512); `--allow-host` в `reactx dev` и `reactx_serve`.

### Исправлено

Исправления, найденные при написании настоящих приложений по llms.txt: `ui::select` с пустым значением («All») в браузере и терминальное окно, которое не закрывалось по Escape. MINOR-релиз, потому что у `Renderer` появилась виртуальная функция, а терминальные окно и уведомления теперь `position: "fixed"`; приложения обновляются без правок.

### Добавлено

- **Прокрутка в терминале**: `overflow: "scroll"` делает `box` вертикальным контейнером с прокруткой. В колонке он занимает оставшиеся строки (высоту считать не нужно); колёсико мыши над ним и PageUp/PageDown прокручивают его, при перемещении фокуса элемент в фокусе остаётся на виду, рамка показывает положение (`┃`), а `onScroll` теперь работает и в терминале (`ScrollEvent` в строках). `TerminalRenderer::scrollBy` / `scrollTop` для кода и тестов.
- `ui::list({.scroll = true})`: длинный список прокручивается внутри рамки, а не растёт; `ui::listItem` держит новый выбранный пункт на виду (оба бэкенда).
- `ref.scrollIntoView()` (`NodeRef`): прокручивает элемент на виду, ровно насколько нужно, в браузере и в терминале (`Renderer::scrollIntoView`).
- `position: "fixed"` в терминале: на экране и поверх всего. Им пользуются `ui::modal`, `ui::confirm` и `ui::toaster()`, поэтому они видны, какой бы длинной ни была страница.

### Исправлено

- `ui::select` (и любой `<option value="">`) в браузере: вариант с пустым значением не выбирался, а его `onChange` присылал подпись («All») вместо `""`.
- Терминальный `ui::modal`, в котором нечему взять фокус (только текст), нельзя было закрыть: Escape до него не доходил. Теперь клавиши идут в открытое окно, когда в нём нет фокуса.
- Терминал: страница выше экрана выталкивала `ui::modal`, `ui::confirm` и уведомления за нижний край.
- `AGENTS.md` новых проектов говорил, что есть только click, input, change, keydown и submit; теперь там все события, компоненты `rx::ui`, как добавить тесты в веб-проект и (терминал) как прокручивать длинные списки.
- llms.txt: тип варианта `ui::select` (`ui::Option`), `onSubmit(text)` у `ui::input`, `asNumber()`/`asInt()`/`asBool()` для значений JSON, тесты в веб-проекте, ошибка при отсутствии поля `key`.

## [0.9.0] — 2026-10-31

C++ встречается со страницей: `useNodeRef` и prop `ref` дают настоящий элемент, `reactx/js.hpp` управляет JavaScript-библиотеками из состояния C++ (демо с Chart.js), а события указателя приносят наведение, перетаскивание и фокус из кода — одинаково в браузере и, с мышью, в терминале (демо-канбан из одного исходника для обоих). `reactx install` теперь проверяет `xz`. MINOR-релиз, потому что в `PropValue` и `EventData` появились новые альтернативы: код, который делает `std::visit` по всем, должен учесть `RefHandler` / `PointerHandler` / `PointerEvent`; остальные приложения обновляются без правок.

### Добавлено

- **Мышь, касания и перетаскивание**: `onPointerDown` / `onPointerMove` / `onPointerUp` (`PointerHandler`, `PointerEvent` с `x`, `y`, `localX`, `localY`, `button`, `buttons`, `type`) и `onMouseEnter` / `onMouseLeave` (не всплывают) — в браузере и в терминале. `{"pointerCapture", true}` после нажатия держит указатель на элементе (слайдеры); без него движения и отпускание получает элемент под указателем (куда бросают).
- **Мышь в терминале**: `TerminalApp` включает SGR-отчёты мыши — клик нажимает кнопки и даёт фокус, наведение, перетаскивание; `app.setMouse(false)` выключает. `decodeInput` / `Terminal::readInput` дают клавиши и `MouseInput`; `TerminalRenderer::handleMouse` и `nodeAt(x, y)`.
- **`ref.focus()`**: `NodeRef` даёт фокус своему элементу из кода, в обоих бэкендах (`Renderer::focus`).
- **Демо: канбан-доска** (`examples/kanban.cpp`): карточки перетаскиваются между колонками мышью или пальцем либо стрелками ← →; один исходник для браузера (`web_kanban`, на странице demos сайта) и терминала (`kanban`).
- **`useNodeRef()` и prop `ref`**: `{"ref", ref}` на HTML-элементе даёт C++ его узел — после коммита, до запуска эффектов, и снова 0, когда элемент убран; копии `NodeRef` видят один и тот же узел. Любой `RefHandler` (`std::function<void(NodeHandle)>`) работает как callback ref. Работает со всеми бэкендами.
- **`reactx/js.hpp`** (браузер): `rx::domElement(ref)` — элемент страницы как `emscripten::val`, чтобы вызывать его методы или отдать JavaScript-библиотеке; `rx::jsValue(json)` — JS-объект из JSON. Линкуйте `reactx::js` (embind); приложения без него embind не несут.
- **Демо: Chart.js из C++** (`examples/web_chart.cpp`, на странице demos сайта): данные — в состоянии C++, график создаётся, обновляется и удаляется из эффектов.

### Изменено

- В `PropValue` ещё одна альтернатива, `PointerHandler`, в `EventData` — `PointerEvent`. `TerminalRenderer::focus` теперь переопределяет `Renderer::focus`.
- В `PropValue` ещё одна альтернатива, `RefHandler`: код, который делает `std::visit` по всем вариантам `PropValue`, должен её учесть. `NodeHandle` теперь объявлен в `reactx/element.hpp` (и по-прежнему доступен через `renderer.hpp`).

### Исправлено

- `install.sh` подсказывает, как добавить `reactx` в PATH, для оболочки пользователя (zsh — `~/.zshrc`, fish — `fish_add_path`; раньше всегда `~/.bashrc`, который zsh не читает), и выводит подсказку последней, после вывода `reactx install`.
- Команда установки на сайте копируется одной строкой: строки-комментарии в ней ломались в zsh (`command not found: #`).
- На странице «Демо» и 404 сайта не было боковых отступов на телефоне (текст упирался в край экрана).
- `reactx install` проверяет `xz` до загрузки Emscripten (его архивы — `.tar.xz`; без `xz`, как в «тонких» контейнерах, `tar` падал на полпути), а при сбое emsdk объясняет, отчего обычно бывает ошибка `tar` и как повторить. Нашёл ИИ-агент (Grok), собиравший проект.

## [0.8.2] — 2026-10-31

Меньше и быстрее в браузере, проще начать: WebAssembly в 2–3,5 раза меньше (счётчик — 40 КБ по сети), `reactx install` скачивает компилятор без sudo, установка одной строкой, `fetch` с заголовками, таймаутом и отменой, ошибки хранилища как значения, строгое чтение JSON, проверка потока у сеттеров и CHANGELOG на английском. Приложения обновляются без правок, кроме редкого `return fetch(...)` из функции, возвращающей `void` (см. «Изменено»).

### Добавлено

- **Сайт на английском**: вся документация, главная и интерфейс — на английском и русском, переключатель EN/RU в шапке (выбор запоминается). По умолчанию английский, русский — если браузер русскоязычный. Заголовок и описание страницы для поисковиков и превью в соцсетях — на английском.
- **`json::Value::require<T>(key)`** — строгое чтение данных извне (импорт, ответ сервера): `std::expected<T, json::Error>`, где нет поля, другой тип, `2.9` для `int` или число, не влезающее в тип, — ошибка с именем поля (`field "points": expected an integer that fits`), а не тихое запасное значение, как у `get<T>`. Работает и в браузерной сборке (без рефлексии).
- **`rx::boolHandler(f)`** — `onChange` флажка с `bool` вместо строк `"true"` / `"false"`: `{"onChange", boolHandler([setDone](bool on) { setDone(on); })}`.
- `ScrollEvent::scrollTop()` / `scrollLeft()` — привычные по DOM имена для `top` / `left`.
- `Setter<T>` и `Dispatch<S, A>` можно создать по умолчанию (поле props, которое никто не заполнил): вызов ничего не делает. Раньше поле типа `Dispatch` в props-структуре нельзя было оставить без значения.
- **Проверка потока у сеттеров**: нативно сеттер, вызванный не из потока, создавшего `Root` (например, из `std::thread`), останавливает программу с `precondition failed: ... onOwnThread()` вместо тихой гонки данных с отрисовкой.
- README, `llms.txt`: таблица частых ошибок компиляции и запуска с объяснениями; в `llms.txt` — что входит в `reactx/reactx.hpp` и какие заголовки подключать отдельно, сигнатура и пример `setLocalFetch`, перебор массивов и объектов JSON, `root.flush()` в тестах после `setState` вне `dispatch`, старый ответ `useFetch` во время `reload()`.
- **Заголовки, таймаут и отмена в `fetch`**: `FetchRequest{.headers = {{"Authorization", "Bearer ..."}}, .timeout = 5s}`; по таймауту приходит ответ со статусом 0 и `error == "timeout after N ms"`. `FetchResponse::headers` и `header("etag")` (без учёта регистра) — заголовки ответа. `fetch` возвращает `FetchHandle`: после `cancel()` колбэк не вызовется, в браузере запрос прерывается (`AbortController`). Работает в браузере и в терминальной сборке.
- **`useFetch(FetchRequest{...})`** — целый запрос с заголовками, таймаутом и методом; перезагружается, когда запрос меняется. `useFetch` теперь отменяет запрос, который заменил (новый url, `reload()`), и запрос размонтированного компонента — раньше он только игнорировал ответ.
- **Ошибки хранилища как значения**: `rx::storageRead(key)` (`std::expected<std::optional<std::string>, std::string>`: нет ключа — `std::nullopt`, а не пустая строка), `rx::storageWrite`, `rx::storageRemove`. `useLocalStorage(key, default, onError)` вызывает `onError`, если сохранить не удалось (переполнена квота, приватный режим) — раньше ошибка записи в браузере терялась молча. Нашёл ИИ-агент, писавший ForgeDesk.
- **`reactx build` следит за размером WebAssembly**: печатает размер `index.wasm` и, если приложение само тянет `std::format` / `std::print` или печать дробных чисел, называет файлы и чем заменить (`+` и `std::to_string`) — каждое из них добавляет ~100 КБ, которые браузер скачивает до первой отрисовки. `reactx_add_app` для этого пишет карту компоновки `<build>/<target>.link.map`.
- **CHANGELOG на английском** (`CHANGELOG.md`); русский переехал в этот файл, `CHANGELOG.ru.md`. Описания релизов на GitHub теперь берутся из английского.
- **`reactx install` — компилятор без sudo, как npm**: скачивает Emscripten 6.0.13 (компилятор для браузера, через emsdk) в `~/.reactx` и, если в системе их нет или они старые, переносимые CMake и Ninja. Системный Emscripten (как в Arch) или `$EMSDK` используются как есть. `reactx build` / `dev` затем находят инструменты сами — без `source emsdk_env.sh`. `--check` только показывает, что есть. Нужны `curl`, `git`, `python3`, `tar`; GCC 16 для терминальных приложений так не скачать. Проверено с нуля: `PATH` без cmake, ninja и emcc → `reactx install` → `reactx new` + `reactx build` без `EMSDK`.
- **Установка одной строкой** на Linux x86-64: `curl -fsSL https://sargisis.github.io/ReactX/install.sh | sh` кладёт готовый `reactx` в `~/.local/bin` и запускает `reactx install`. Скрипт — `install.sh` в репозитории, публикуется вместе с сайтом.

### Изменено

- **WebAssembly в 2–3,5 раза меньше, страницы открываются быстрее**: счётчик — 91 КБ вместо 332 КБ (по сети 40 КБ вместо 146 КБ, gzip), сайт — 269 КБ вместо 630 КБ (109 КБ вместо 249 КБ). Под мобильным профилем Lighthouse (150 мс, 1,6 Мбит/с, процессор ×4) LCP главной сайта — 1,2 с вместо 2,1 с. Что сделано:
  - `REACTX_PRE` в браузерной сборке больше не печатает через `std::println`: один такой вызов тянул в каждое приложение весь `std::format` (~100 КБ).
  - Дробные числа в props и JSON в браузере переводятся в текст самим браузером (`String(x)`, тоже кратчайшая точная запись) вместо `std::to_chars` из libc++ с его таблицами (~110 КБ). Нативно — по-прежнему `std::to_chars`.
  - Release-сборки для браузера компилируются с `-Oz` вместо `-O3` (на ~25% меньше); вернуть `-O3` — `-DREACTX_WEB_OPTIMIZE_SIZE=OFF`.
  - Шаблоны страниц (`web/*_shell.html`) просят `index.wasm` сразу (`<link rel="preload">`), а не после загрузки `index.js`; шрифты сайта больше не задерживают первую отрисовку.
- `rx::fetch` возвращает `FetchHandle` вместо `void`. Код, который его не использует, не меняется; эффект вида `useEffect([] { return fetch(...); })` теперь отменяет запрос при очистке. Формально это несовместимое изменение (`void f() { return fetch(...); }` больше не компилируется), поэтому оно упомянуто здесь.
- `useLocalStorage`: сохранённая пустая строка после перезагрузки читается как `""`, а не как значение по умолчанию.
- «Быстрый старт» переписан для новичков простым языком: что такое ReactX, установка готового `reactx`, приложение за три команды, первый компонент, как писать с ИИ-помощником; сборка самого ReactX из исходников — в конце. На главной шаг установки — готовый бинарник вместо сборки из исходников.

### Исправлено

- README: для macOS сборка из исходников указывала `g++-14`, хотя нужен GCC 16+; теперь `g++-16`. Примеры больше не называют ReactX фреймворком на «C++20».
- `reactx dev` с `"web": {"base": "/pulseboard/"}` показывал белый экран: страница запрашивала `/pulseboard/style.css`, `/pulseboard/index.wasm`, а сервер отдавал файлы только от корня. Теперь файлы и автообновление работают под базовым путём (как на GitHub Pages), `/` перенаправляет на него, а в консоли печатается правильный адрес. Нашёл ИИ-агент, писавший PulseBoard.

## [0.7.0] — 2026-10-27

Границы ошибок, общее состояние (`createStore` / `useStore`), `useId`, сеть в терминальных приложениях; ядро быстрее на больших списках и с минимумом перестановок узлов; исправлены утечка памяти в контексте, порча дерева после исключения, `<select>` и `javascript:`-ссылки в браузере. ### Добавлено

- **`errorBoundary(fallback, children)`** — граница ошибок, как в React: если дети бросили исключение при отрисовке (при монтировании или позже, при обновлении состояния), вместо них показывается `fallback(RenderError)`, а остальное приложение работает. `RenderError` — `message`, `exception` и `retry()`, чтобы попробовать снова. Если бросил сам запасной вариант, ошибку ловит следующая граница выше.
- **`createStore` / `useStore`** — общее состояние вне дерева (как Zustand): `Cart.set(v)` / `Cart.update(f)`; `useStore(Cart)` перерисовывает при каждом изменении, `useStore(Cart, selector)` — только когда меняется выбранная часть.
- **`useId()`** — id, уникальный в приложении и одинаковый при каждой отрисовке (для `<label for>` и `aria-*`).
- **`fetch` / `useFetch` в терминальной сборке ходят в сеть**: полный `http://`-URL, запрос в своём потоке, ответ — в потоке интерфейса на ближайшем `flush()`. Раньше без `setLocalFetch` запросы сразу завершались ошибкой «no network».
- `reactx_bench` — замеры ядра на больших списках (не тест): `./build/release/reactx_bench [строк]`.

### Изменено

- **Ядро быстрее на больших списках** (`reactx_bench`, 10 000 строк с ключами): перерисовка без изменений 35 → 8 мс, обмен двух строк 56 → 9 мс, 50 000 строк, смонтированных и удалённых под одним провайдером контекста, 833 → 68 мс.
- **Минимум перестановок узлов**: `sync` оставляет на месте узлы на самой длинной возрастающей подпоследовательности старых позиций и вставляет остальные по одному разу. Обмен двух строк из 10 000 — 2 перестановки вместо 9 997, удаление каждой второй строки — ни одной вместо 4 998 (в браузере каждая — операция DOM, сбрасывающая фокус и выделение).
- Браузер: `checked` у флажков и переключателей — управляемый, как `value`: если `onChange` не изменил состояние, клик отменяется (у переключателя — для всей группы), как в React.

### Исправлено

- **Утечка памяти в контексте**: компоненты, читавшие контекст, оставались в списке провайдера, пока его значение не изменится; под постоянным провайдером (тема) память росла с каждой строкой, которая когда-либо была на экране, а чтение контекста замедлялось квадратично. Теперь подписка снимается при размонтировании, поиск — O(1).
- **Исключение при отрисовке портило дерево**: наполовину построенные fiber'ы оставались зарегистрированными (висячие указатели, по которым шло следующее событие), а эффекты не очищались. Теперь неудачное поддерево размонтируется.
- Если неперехваченное исключение прерывало пакет обновлений, остальные компоненты пакета оставались помеченными, но вне очереди — их `setState` больше никогда не перерисовывал. Теперь они остаются в очереди.
- **Браузер, безопасность**: `href`, `src`, `action`, `formaction`, `xlink:href`, `poster`, `cite` со ссылкой `javascript:` (по правилу React: с управляющими символами, пробелами и переводами строк внутри, в любом регистре) заменяются на `about:blank#blocked` с ошибкой в консоли — ссылка из пользовательских данных больше не выполняет код при клике.
- Браузер: управляемый `<select value=...>` при первой отрисовке показывал не тот вариант (значение ставилось до появления `<option>`), а с `onChange` его вообще нельзя было переключить — событие `input` возвращало старое значение раньше, чем `change` сообщал о выборе.
- Модуль `import reactx;` не экспортировал `useReducer`, `Dispatch`, `useTimeout`, `useInterval` и `useKeyboard` из v0.5.

- **Компоненты `rx::ui`** с темой — один код для терминала и браузера: `button`, `input`, `checkbox`, `tabs`, `modal`, `list` / `listItem`.
- **Роутер** `rx::router`: маршруты с параметрами и `*`, ссылки без перезагрузки, History API, базовый путь из `<base href>`.
- **Данные**: `useFetch`, `fetch`, `setLocalFetch` («сервер внутри приложения»); свой **JSON** `rx::json`.
- **HTTP-сервер на C++** `rx::net::HttpServer`: файлы с правильными типами, маршруты с параметрами, SPA-режим, URL-префикс и страница 404; программы `reactx_serve` и `api_server` (REST API задач).
- **CLI `reactx`**: `new` (веб или `--terminal`), `dev` (встроенный сервер, пересборка и автообновление страницы), `build`, `add` / `remove` зависимостей; `reactx_add_app()` для своих CMake-проектов.
- **Сайт с документацией** на ReactX: https://sargisis.github.io/ReactX/, публикуется GitHub Actions через ветку `gh-pages`.
- Версия в одном месте (`project(ReactX VERSION ...)`) → `reactx/version.hpp`, `rx::version()`; новые проекты из `reactx new` подключают ReactX по тегу релиза.
