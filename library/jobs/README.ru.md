# reactx::jobs

Фоновая работа для серверов на [ReactX](https://github.com/sargisis/ReactX): отправить письмо после того, как ответ ушёл, повторить неудавшийся вебхук, чистить данные каждую ночь. Задачи выполняются в рабочих потоках; задача, бросившая исключение, повторяется позже.

In English: [README.md](README.md).

```cpp
#include "rx/jobs.hpp"
using namespace rx;
using namespace std::chrono_literals;

jobs::Queue jobs({
    .workers = 4,
    .onFailed = [](const jobs::Failure& f) { std::println(stderr, "{} не удалась: {}", f.name, f.error); },
});

jobs.add("welcome email", [to] { sendMail(to, "Добро пожаловать!"); });       // сейчас; 3 попытки
jobs.add("webhook", [=] { post(url, body); }, {.attempts = 5, .delay = 2s});   // 2 с, 4 с, 8 с, 16 с
jobs.after(10min, "reminder", [] { remind(); });
auto health = jobs.every(30s, "health check", [] { check(); });
jobs.cron("0 3 * * *", "nightly cleanup", [] { cleanup(); });                   // 03:00 по местному времени
jobs.cancel(health);
```

Задача сообщает об ошибке исключением (любым; причина — `std::exception::what()`). Разовые задачи (`add`, `after`) повторяются `attempts` раз с растущей паузой (`delay`, ×`backoff`, не больше `maxDelay`), затем вызывается `onFailed`. Повторяющаяся задача (`every`, `cron`), которая упала, попадает в отчёт и всё равно запускается в следующий раз.

## Подключение

Идёт вместе с ReactX (с 1.7), для нативной сборки (сервер). В `CMakeLists.txt` проекта:

```cmake
target_link_libraries(my_server PRIVATE reactx::jobs)
```

## Очередь

| Вызов | |
|---|---|
| `add(name, work, retry)` | как только освободится поток |
| `after(delay, name, work, retry)` | один раз, через `delay` |
| `every(period, name, work)` | каждые `period` (первый раз — через один период) |
| `cron(spec, name, work)` | по расписанию; `std::expected` (непонятное расписание — ошибка) |
| `cancel(id)` | `false`, если задачи уже нет; выполняющаяся доработает |
| `stats()` | `waiting`, `running`, `done`, `failed` |
| `wait()` | пока не закончатся все разовые задачи (с повторами) |
| `stop()` | выполняющиеся доработают, ожидающие отбрасываются (то же делает деструктор) |

`Options`: `workers` (0 — по одному на ядро) и `onFailed`. `Retry`: `attempts` (3), `delay` (1 с), `backoff` (2), `maxDelay` (10 мин).

## Cron

`"минута час день месяц день_недели"` по местному времени; каждое поле — число, `*`, список `1,15`, диапазон `1-5` или шаг `*/10` (`5/15` — с 5-й, каждые 15). Воскресенье — 0 или 7. Если заданы и день, и день недели, подходит любой из них (как в cron).

| Расписание | |
|---|---|
| `0 3 * * *` | в 03:00 каждый день |
| `*/5 9-18 * * 1-5` | каждые 5 минут, 9:00–18:55, с понедельника по пятницу |
| `0 0 1 * *` | в полночь 1-го числа каждого месяца |
| `30 12 * * 0` | по воскресеньям в 12:30 |

`rx::jobs::nextCron(spec, from)` даёт следующее время, подходящее под расписание.

Задачи выполняются в рабочих потоках, а не в UI-потоке: общие данные защищайте мьютексом и не вызывайте setter компонента из задачи. С `reactx::db` задача может сразу читать и писать хранилище (оно потокобезопасно).
